## 전달 방법 — 두 가지를 같이

안티그래비티는 **파일 첨부**와 **텍스트 지시**를 함께 받는 게 가장 잘 됩니다.

### ① 파일로 넣을 것
- `02_프로토타입.html` — "이렇게 동작해야 한다"는 기준. 열어서 눌러보라고 하세요.
- `03_안티그래비티_작업지시서.md` — 단계별 지시 원본.
- `backup-firestore.mjs`, `restore-firestore.mjs`, `01_백업복구_가이드.md` — 백업/복구.

### ② 텍스트로 넣을 것 (첫 메시지)
아래를 그대로 복사해 붙여넣으세요.


## 진행 순서 (11단계)

작업지시서 안에 각 단계의 **완료 조건**이 적혀 있습니다. 그대로 붙여 쓰세요.

0. **백업** — `backup-firestore.mjs` 실행. (한 줄도 시작 전에!)
1. 회의실을 resources 구조로 이관
2. 사용 시작·종료 기록
3. 워크룸 추가 (예약제, 정원 3명)
4. 동시 예약 차단 (Firestore 보안 규칙)
5. 뱀부랩 1·2 (24시간, 자정 넘김)
6. 대장(현황) 검색
7. 관리자 통계
8. **사용 기록 검색** (이름·프로젝트, 한글)
9. **알림** (앱 내 + 슬랙/푸시) ← 선행 결정 필요, 아래 참고
10. **첫 이용 가이드** (온보딩, 노출 기준)
11. **마이페이지** (설정, 관리자 분기)

## 알림 방식 (이미 정해짐)

- **발송**: 브라우저 알림 + 홈 화면에 추가한 웹앱(PWA) 알림. 슬랙 안 씀.
- **Firebase**: 무료(Spark) 플랜.

무료 플랜에서 되는 것과 안 되는 것을 정확히 알아두세요.
- **앱 내 알림(종 아이콘)** — 무료로 완전히 됩니다. 이게 기본입니다.
- **앱이 열려 있는 동안 브라우저 알림** — 됩니다. 5분 전 알림, 자동 취소도 이 방식.
- **앱을 완전히 닫아도 오는 푸시** — 무료로는 안 됩니다. 정해진 시각에 서버가
  알아서 보내려면 Cloud Functions(유료 Blaze)가 필요합니다. 이건 나중에 올릴 때
  붙이고, 지금 만든 구조를 그대로 재사용합니다.

작업지시서 9단계에 이 내용이 완료 조건까지 다 반영돼 있습니다.

## 첫 실행 시 데이터 상태 (중요)

바로 가져다 실행했을 때 반드시 이래야 합니다.

- **기존 회의실 예약은 한 건도 사라지지 않고 그대로 유지됩니다.**
  1단계는 예약 문서를 지우지 않고 `resourceId` 필드만 채우는 마이그레이션입니다.
- **워크룸·뱀부랩 프린터는 예약 0건, 빈 상태로 시작합니다.**
  아무도 아직 안 썼으니까요. 시드로 넣는 건 정책 문서뿐입니다.
- ⚠️ 시안(02_프로토타입.html)에 보이는 워크룸·프린터 예약(경선님·여준님·태영님 등)은
  **화면을 보여주려는 데모 샘플**입니다. 이 데이터를 DB에 넣으면 안 됩니다.
  작업지시서 맨 앞 "절대 규칙 0" 에 이 내용이 못박혀 있습니다.

## 품질 확인은 이렇게 했습니다 (참고)

시안(02_프로토타입.html)은 눈으로만 만든 게 아니라, 자동 테스트로 검증했습니다.
안티그래비티가 각 단계를 끝낼 때 아래를 똑같이 확인하면 됩니다.

- **정원·겹침**: 워크룸은 어느 순간에도 3명을 넘지 않는다. 프린터는 기계별 이중 예약이 없다.
- **수정도 예약과 똑같이** 겹침 검사를 받는다.
- **빈 시각 예약 차단**: 시작·종료가 비어 있으면 막힌다. (20명 시뮬레이션에서 나온 실제 버그)
- **한글 검색**: 사용 기록에서 이름·프로젝트가 한글로 검색된다.
- **가이드 노출**: 첫 로그인·하루 이상 미접속엔 전체, 새 자원 추가 시엔 그 부분만.
- **role 분기**: 관리자가 아니면 마이페이지 관리 구역이 안 보인다.

## 한 가지 주의

시안은 데모라 현재 시각이 **오후 6시 43분으로 고정**돼 있고, 저장(localStorage)이
막힌 환경이라 가이드가 매번 뜹니다. 실제 사이트에서는 진짜 시각과 로그인 계정을
쓰므로 작업지시서 10단계의 노출 기준(guideSeen / lastSeenAt)대로 동작합니다.
