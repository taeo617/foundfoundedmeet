회의실 예약 앱 → 사내 자원 예약 플랫폼 확장.
**한 번에 한 단계씩**, 각 단계는 되돌릴 수 있는 크기로 자릅니다.

---

## 시작 전 (10분)

| | 확인 |
|---|---|
| 1 | `node backup-firestore.mjs` 실행 완료, `_meta.json` 문서 수가 콘솔과 일치 |
| 2 | 임시 프로젝트에 복구 리허설 1회 완료 |
| 3 | `git checkout -b feat/resources` — main 은 손대지 않습니다 |
| 4 | `.gitignore` 에 `serviceAccountKey.json`, `backups/`, `.env*` |
| 5 | Vercel 프리뷰 배포가 켜져 있는지 (브랜치 푸시 → 프리뷰 URL) |

**백업 전에는 한 줄도 시작하지 마세요.** 1단계가 기존 예약 데이터를 건드립니다.

## 1. 컨텍스트 파일부터 심습니다

에이전트한테 매 프롬프트마다 "우리 앱은 이렇고요…"를 반복하면 금방 지칩니다. 저장소 루트에 규칙 파일을 하나 두면 모든 요청에 자동으로 딸려 갑니다.

> 안티그래비티는 저장소 루트의 `AGENTS.md` 를 읽습니다. 워크스페이스 룰 UI가 있다면 거기에 같은 내용을 넣어도 됩니다.

**`AGENTS.md` — 아래를 그대로 복사해 만드세요.**

````markdown
# foundfoundedmeet — 에이전트 작업 규칙

## 이 앱이 무엇인가
사내 자원 예약 PWA. 원래는 회의실 예약 전용이었고, 지금은
회의실 / 워크룸 / 3D 프린터(뱀부랩 1·2) 를 다루는 구조로 확장하는 중입니다.

## 스택
React + Vite + Tailwind v4 + Firebase(Firestore, Auth) / Vercel 배포 / 데스크톱 웹 + PWA

## 절대 규칙
0. **기존 회의실 예약은 한 건도 없어지면 안 됩니다. 워크룸·프린터는 빈 상태로 시작합니다.**
   - 회의실 예약 문서는 **삭제·초기화하지 않습니다.** 1단계는 기존 문서에 `resourceId` 필드만
     채우는 마이그레이션입니다. 예약 내용·시간·참석자는 그대로 둡니다.
   - 워크룸과 프린터는 **아무도 아직 안 썼으므로 예약이 0건이어야 합니다.**
     시드 스크립트로 넣는 것은 `resources/{id}` **정책 문서 1개뿐**입니다.
     예약(reservations)·세션(sessions) 문서는 만들지 마세요.
   - ⚠️ `02_프로토타입.html` 에는 **데모용 가짜 예약**이 들어 있습니다
     (경선님·여준님 워크룸 사용 중, 태영님 뱀부랩 출력 중 등). 이건 화면이 어떻게
     보이는지 보여주려고 넣은 **샘플**입니다. **이 예약들을 DB에 시드하지 마세요.**
     시안에서 가져올 것은 레이아웃·색·컴포넌트 구조뿐이고, 데이터는 빈 상태에서 출발합니다.
   - 첫 배포 직후 정상 상태: 회의실에는 기존 예약이 그대로, 워크룸·프린터는
     "지금 아무도 없음 / 정원 N명" 빈 카드.
1. **자원별로 코드를 복사하지 않습니다.** 자원의 차이는 코드가 아니라
   Firestore `resources/{id}.policy` 필드로 표현합니다.
   새 장비가 생기면 문서 한 개 추가로 끝나야 합니다.
   `if (resourceId === 'workroom')` 같은 분기가 보이면 잘못 가고 있는 겁니다.
2. **시각은 항상 서버 타임스탬프**(`serverTimestamp()`)를 씁니다.
   클라이언트 `new Date()` 를 DB에 저장하지 않습니다.
3. **기록은 지우지 않습니다.** 수정이 필요하면 수정 이력을 남깁니다.
4. **사람 이름 · 호칭 · 소속 표기는 기존 코드 규칙을 그대로 따릅니다.**
   새 규칙을 만들거나 임의의 팀 이름을 지어내지 마세요.
   - 멤버 목록은 **기존 데이터 소스 하나**에서만 가져옵니다. 화면마다 배열을 따로 만들지 않습니다.
   - 호칭(`님` 붙이는지), 그룹 이름(디렉터 / 임직원), 직함 문구(디렉터, 시니어 디자이너,
     디자이너, 프리랜서 디자이너, 인턴), 배지(ID / VD) — 전부 지금 코드에 있는 값을 씁니다.
   - 어디서는 `님`을 붙이고 어디서는 안 붙이는 차이가 있다면, 그것도 **현재 화면 그대로** 유지합니다.
     (예: 참석자 칩은 이름만, 참석자 선택 창은 `이름 + 님`)
   - "기획팀", "개발팀" 같은 조직 단위가 코드에 없다면 만들지 마세요. 직함으로 표시합니다.
   - 새 필드가 필요하면 먼저 물어보고, 임의로 스키마를 늘리지 않습니다.
5. **화면 구조를 바꾸지 않습니다.** 상단 내비, 서브바(타임라인/캘린더 전환),
   날짜 스트립, 자원 알약, 상태 카드, 타임라인, 하단 검은 버튼 —
   이 배치는 고정입니다. 새 자원은 이 뼈대에 **내용만 갈아 끼웁니다.**
6. **디자인 토큰을 새로 만들지 않습니다.** 색은 전부 기존 CSS 변수에서 가져옵니다.
   - 상태 카드: 사용 가능 `--mob-free-bg`, 사용 중/만석 `--mob-busy-bg`
   - 타임라인 카드: `--mob-card-normal` + 좌측선 `--mob-line-normal`
     (특이 상태는 `--mob-card-urgent` / `--mob-line-urgent`)
   - 텍스트·경계: `--text` `--muted` `--faint` `--border` `--line`
   - 히트맵(통계): `--heat-0` ~ `--heat-4`
   하드코딩 hex, Tailwind 기본 팔레트(`bg-blue-500`, `text-green-600` 등) 금지.
   다크모드는 `.dark` 클래스 기준으로 이미 동작합니다.
7. 서체는 Pretendard Variable. 새 폰트를 추가하지 않습니다.

## 데이터 모델
```
resources/{resourceId}
  name, type: 'space' | 'equipment', order: number, active: bool
  policy: {
    requiresReservation: bool   // 워크룸 false
    requiresApproval: bool
    requiredCerts: string[]     // 회의실 [], 뱀부랩 ['3dp-safety']
    capacity: number            // 회의실 1, 워크룸 4, 프린터 1
    allowOverlap: bool          // 워크룸만 true (capacity 까지)
    requiresReport: bool        // 프린터만 true
    slotMinutes: 30
    openHours: { days: number[], from: '09:00', to: '22:00' }  // 프린터는 24시간·주말
    autoCancelMinutes: number | null   // 워크룸 10, 나머지 null
    remindBeforeMinutes: number | null // 워크룸 5
    allowUrgentOverride: bool          // 회의실만 true
    notice: string[]                   // 주의사항 문구, 회의실은 []
  }

reservations/{resourceId}_{yyyyMMdd}_{slotIndex}   ← 결정적 ID (중요)
  resourceId, userId, date, slotIndex, start, end,
  status: 'booked' | 'cancelled' | 'done', title?, attendees?, createdAt

sessions/{autoId}                                  ← 실제 사용 기록
  resourceId, userId, reservationId?,
  checkInAt, checkOutAt, autoClosed: bool,
  source: 'button' | 'qr' | 'admin',
  report?: { result: 'success'|'partial'|'fail', filamentG?: number, note?: string }
  edits?: [{ by, at, field, before, after }]

users/{uid}
  name, dept, role: 'member' | 'admin', certs: string[]
```

## 작업 방식
- 요청을 받으면 **먼저 계획을 보여주고 승인을 기다립니다.** 승인 전에 파일을 쓰지 않습니다.
- 한 번에 한 단계만. 시키지 않은 리팩터링을 끼워 넣지 않습니다.
- 데이터 마이그레이션 스크립트는 항상 dry-run 모드를 기본으로 만듭니다.
- 작업이 끝나면 **무엇을 어떻게 확인하면 되는지** 검증 절차를 알려줍니다.
````

## 2. 요청할 때 지킬 것 네 가지

에이전트한테 뭘 시키느냐보다 **어떻게 자르느냐**가 결과를 좌우합니다.

**① 계획을 먼저 받습니다.**
바로 코드부터 쓰게 두면 30개 파일이 바뀐 뒤에야 방향이 틀린 걸 알게 됩니다. 매 단계 첫 문장은 이겁니다.

> 코드를 쓰기 전에 계획부터 보여주세요. 어떤 파일을 만들고 어떤 파일을 고칠 건지, 각각 왜 그런지. 제가 승인하면 그때 시작하세요.

**② 완료 조건을 숫자로 줍니다.**
"잘 만들어줘"는 검증이 불가능합니다. 아래 각 단계의 *완료 조건*을 프롬프트에 그대로 붙여넣으세요.

**③ 한 단계 = 한 커밋 = 한 프리뷰 배포.**
단계가 끝날 때마다 푸시하고 프리뷰 URL에서 직접 눌러봅니다. 두 단계를 몰아서 하면 뭐가 깨뜨렸는지 못 찾습니다.

**④ 막히면 되돌립니다.**
같은 문제로 세 번 이상 왕복하면 고치려 하지 말고 `git reset --hard`, 요구사항을 더 잘게 쪼개서 다시 요청하세요. 에이전트와의 긴 논쟁은 거의 항상 손해입니다.

| # | 단계 | 화면 변화 | 위험도 |
|---|---|---|---|

| 2 | 사용 시작·종료 → `sessions` 기록 | 버튼 추가 | 낮음 |

| 5 | 뱀부랩 1·2 추가 (자격 + 사용 보고) | 큼 | 중간 |
| 6 | 대장 검색 화면 | 큼 | 낮음 |
| 7 | 관리자 통계 | 큼 | 낮음 |

1·2번은 겉보기에 아무것도 안 바뀌지만 나머지 전부가 여기 올라탑니다. 건너뛰고 싶은 유혹이 제일 큰 구간이기도 합니다.

## 1단계 — 회의실을 resources 구조로 이관

````
코드를 쓰기 전에 계획부터 보여주세요. 승인하면 시작합니다.

[목표]
지금 회의실 예약 로직이 '회의실'을 코드에 박아둔 상태입니다. 이걸 Firestore의
resources 컬렉션에서 읽어오는 구조로 바꿉니다.
**화면과 동작은 지금과 100% 동일해야 합니다.** 순수 구조 변경입니다.

[할 일]
1. AGENTS.md 의 데이터 모델대로 resources/meeting-room 문서 1개를 만드는
   시드 스크립트를 작성 (scripts/seed-resources.mjs)
   - 회의실 policy: requiresReservation true, capacity 1, allowOverlap false,
     requiredCerts [], requiresReport false, autoCancelMinutes null,
     allowUrgentOverride true, notice [], openHours 평일 09:00–22:00
2. 기존 예약 문서에 resourceId: 'meeting-room' 필드를 채우는 마이그레이션
   스크립트 (scripts/migrate-reservations.mjs)
   - 기본 dry-run. --confirm 플래그가 있을 때만 실제 쓰기
   - 이미 resourceId 가 있는 문서는 건너뜀 (여러 번 돌려도 안전할 것)
3. 자원 정보를 읽는 훅 useResources() 추가 — resources 를 구독하고 정책을 노출
4. 회의실 화면이 하드코딩 값 대신 이 훅에서 정책을 받도록 교체
   (운영시간, 슬롯 길이, 정원 등)

[하지 말 것]
- UI 마크업, 클래스명, 레이아웃 변경
- 워크룸/프린터 관련 코드 미리 만들기
- 시키지 않은 파일 정리나 포매팅

[완료 조건]
- 화면 스크린샷이 작업 전후로 동일
- 기존 예약이 전부 그대로 보이고, 새 예약도 정상 생성됨
- 회의실 운영시간을 Firestore 에서 09:00→10:00 으로 바꾸면
  배포 없이 화면에 반영됨  ← 이게 이 단계의 진짜 검증입니다
- 코드 어디에도 '회의실' 문자열이 하드코딩돼 있지 않음

[작업 후]
검증 방법을 순서대로 알려주세요.
````

**직접 확인할 것**
- 마이그레이션을 dry-run 으로 먼저 돌려 출력된 건수가 콘솔 문서 수와 맞는지
- `--confirm` 후 Firestore 콘솔에서 예약 문서 몇 개 열어 `resourceId` 확인
- 운영시간 바꿔보기 → 안 바뀌면 아직 하드코딩이 남아 있는 겁니다

## 2단계 — 사용 시작·종료 기록

````
계획 먼저 보여주세요.

[목표]
예약과 별개로 '실제로 썼다'는 기록을 sessions 컬렉션에 남깁니다.
예약은 미래의 약속, 세션은 과거의 사실입니다. 두 개를 절대 한 문서에 합치지 마세요.
이 둘이 나뉘어 있어야 나중에 노쇼율이 자동으로 계산됩니다.

[할 일]
1. 자원 상세 화면에 '사용 시작' / '사용 종료' 버튼 추가
2. 시작 → sessions 문서 생성
   { resourceId, userId, reservationId?, checkInAt: serverTimestamp(),
     autoClosed: false, source: 'button' }
3. 종료 → checkOutAt: serverTimestamp() 로 업데이트
4. 내가 진행 중인 세션이 있으면 버튼이 '사용 종료'로 바뀌고,
   앱 어디서든 진행 중 상태가 보이게 (상단 바 등)
5. Cloud Functions 스케줄러: 매일 자정 KST 에 checkOutAt 이 없는 세션을
   닫고 autoClosed: true 를 남김
   - 프린터처럼 24시간 자원은 checkInAt 기준 N시간 후에 닫도록 policy 로 제어

[규칙]
- 시각은 전부 serverTimestamp(). new Date() 를 저장하지 마세요.
- autoClosed: true 인 세션은 나중에 통계에서 제외됩니다. 지금은 플래그만 정확히.

[완료 조건]
- 시작 → 종료 후 Firestore 에 checkInAt/checkOutAt 이 서버 시각으로 들어감
- 브라우저 시계를 바꿔도 저장되는 시각이 안 변함
- 종료를 안 누른 세션이 자정 이후 autoClosed: true 로 닫힘
  (Functions 에뮬레이터에서 수동 트리거로 확인)
````

## 3단계 — 워크룸 추가

여기서부터 화면이 크게 바뀝니다. **`02_디자인시안.html` 을 안티그래비티에 파일로 첨부하고** 아래를 넣으세요.

````
계획 먼저 보여주세요. 첨부한 02_디자인시안.html 을 먼저 열어보고,
거기 쓰인 CSS 변수와 컴포넌트 구조를 그대로 따르세요.

[목표]
예약이 없는 자원(워크룸)이 잘 도는지로 1단계 추상화를 검증합니다.
워크룸 전용 분기(if resourceId === 'workroom')를 만들면 실패입니다.

[워크룸 정책]
capacity 3, requiresReservation true, allowOverlap true(정원 안에서),
requiredCerts [], requiresReport false,
openHours 평일 09:00–22:00, autoCancelMinutes 10, remindBeforeMinutes 5,
notice: [
````

## 9단계 — 알림 (앱 내 + 브라우저/홈화면 푸시)

> **확정된 조건**
> - 발송 방식: **브라우저 알림 + 홈 화면에 추가한 웹앱(PWA) 알림.** 슬랙 안 씀.
> - Firebase 요금제: **무료(Spark).**
>
> ⚠️ 무료 플랜의 한계를 먼저 이해하고 가세요.
> - **앱 내 알림(종 아이콘)** 은 무료로 완전히 됩니다. 이게 기본입니다.
> - **브라우저/PWA 푸시**(앱이 꺼져 있어도 뜨는 알림)를 보내려면 보내는 주체(서버)가
>   필요한데, 무료 Spark 플랜은 Cloud Functions(=예약 스케줄러)를 못 씁니다.
> - 그래서 **"예약 5분 전"·"10분 경과 자동 취소" 처럼 정해진 시각에 서버가 알아서
>   보내는 푸시는 무료로는 안 됩니다.** 이건 사실대로 사용자에게 알리세요.
> - 무료로 가능한 현실적인 방식은 **"앱이 열려 있는 동안" 브라우저 알림**입니다.
>   누군가 앱을 켜 두면 그 사람의 예약 시간이 다가올 때 브라우저 알림이 뜹니다.
>   자동 취소도 "앱을 연 사람이 있을 때 클라이언트가 확인해서 처리 + 보안 규칙으로 검증"
>   방식으로 무료 범위에서 구현합니다.

````

[9-1. 앱 내 알림함 — 무료로 완전히 됨. 이게 핵심]

[9-2. 브라우저 / 홈화면(PWA) 알림 — 앱이 열려 있는 동안]
6. PWA 설정: manifest.json + 서비스워커 등록.
   "홈 화면에 추가" 하면 앱처럼 실행되게. (아이콘·이름·테마색)
7. 알림 권한 요청: 마이페이지 알림 설정에서 "브라우저 알림 켜기"를 눌렀을 때만
   Notification.requestPermission() 호출. 거부해도 앱 내 알림함은 그대로 동작.
8. 앱이 열려 있는 동안, 다가오는 내 예약 시각(5분 전)에 브라우저 알림(new Notification).
   - 클라이언트 타이머로 확인. 여러 탭 중복 방지.
9. 자동 취소(워크룸 10분 미시작): 앱을 연 사용자의 클라이언트가 조건을 감지하면
   status:'cancelled' 로 바꾸고 알림. **문서를 지우지 말 것**(노쇼 통계).
   보안 규칙에서 "예약 시각 + autoCancelMinutes 지난 미시작 예약만 cancelled 로 변경 가능"
   을 검증해, 아무도 임의로 취소 못 하게 막습니다.

[9-3. 사용자에게 솔직히 안내]
10. 마이페이지 알림 설정에 한 줄:
    "앱을 닫아도 오는 알림은 준비 중입니다. 지금은 앱을 열어두면 브라우저 알림이 옵니다."
11. 마이페이지 알림 항목 토글(확정·5분 전·자동취소·자리 남·조용한 시간)을
    실제로 반영 — 끄면 그 알림(앱 내·브라우저 둘 다)이 안 뜸.

[완료 조건]
- 예약하면 즉시 내 알림함에 확정 알림이 뜸 (무료로 됨)
- 마이페이지에서 항목을 끄면 그 알림이 안 옴
- 브라우저 알림을 켜고 앱을 열어둔 채로 예약 5분 전이 되면 브라우저 알림이 뜸
- 홈 화면에 추가하면 앱 아이콘으로 실행되고 알림이 동작
- 10분 지난 미시작 워크룸 예약이 (앱을 연 사람이 있을 때) cancelled 로 바뀌고,
  그 문서가 삭제되지 않고 남아 있음
- 앱을 완전히 닫은 상태에서 오는 푸시는 이번 범위가 아님 (Blaze 전환 시 추가)

[나중에 — 앱을 닫아도 오는 진짜 푸시가 필요해지면]
- Firebase Blaze(유료·종량제)로 올리고 Cloud Functions 스케줄러 + FCM 을 붙이면
  "5분 전"·"자동 취소" 를 서버가 정확히 보냅니다. 지금 만든 구조(notifications 컬렉션,
  토글, 서비스워커)는 그대로 재사용됩니다.
````

## 10단계 — 첫 이용 가이드 (온보딩)

````
계획 먼저 보여주세요. 프로토타입의 온보딩 동작을 그대로 옮깁니다.

[노출 기준 — 사용자 문서에 저장]
- guideSeen: string[]   (본 자원 그룹: 'meeting','workroom','printer')
- guideVersion: string  (가이드 대개편 시 올림)
- lastSeenAt: timestamp

판정:
1. guideSeen 이 비어 있음(첫 로그인)      → 전체 가이드
2. guideVersion 이 현재와 다름            → 전체 가이드
3. FEATURES 중 guideSeen 에 없는 자원 존재 → 그 자원 가이드만 (부분)
4. lastSeenAt 이 24시간보다 오래됨        → 전체 가이드
5. 그 외                                  → 안 띄움

[할 일]
1. 스텝: intro 1 + 회의실 2 + 워크룸 2 + 프린터 2 + 공통 2 = 총 9.
   각 스텝은 필요하면 해당 자원 화면으로 전환한 뒤 그 자리를 스포트라이트.
2. 화면을 어둡게 + 대상만 밝게 + 카드로 설명 + 다음/건너뛰기.
   모바일은 카드를 하단 고정.
3. 부분 가이드일 때 intro 문구를 '새 기능 추가' 톤으로.
4. 끝나거나 건너뛰면 guideSeen/guideVersion/lastSeenAt 갱신.

[업데이트 알림과 연동]
5. FEATURES 에 자원이 추가되면 그 자원의 업데이트 알림에 '새로 추가됨' 배지.
6. 업데이트 알림마다 '가이드 보기' 버튼 → 그 자원 가이드만 실행.
7. 업데이트 알림은 자원별로 하나씩 (회의실/워크룸/프린터 따로).
   한 알림에 다 몰지 마세요.

[완료 조건]
- 첫 로그인 계정에서 9스텝 전부 뜨고, 워크룸 스텝에서 실제 워크룸 화면으로 바뀜
- 다 본 계정은 재접속해도 안 뜸
- guideSeen 을 ['meeting'] 로 만들어두면 워크룸·프린터 가이드만 뜸
- 24시간 지난 것처럼 lastSeenAt 을 과거로 바꾸면 전체가 다시 뜸
- 알림 '가이드 보기' → 그 자원 스텝만 실행됨
- 모바일(390px)에서 온보딩이 에러 없이 끝까지 진행됨
````

## 11단계 — 마이페이지 (설정)

````
계획 먼저 보여주세요. 기존 "회의실 현황 대시보드" 개인 화면을 설정 중심으로 재편합니다.

[구조 — role 로 분기]
1. 계정: 이름·사진 변경 / 비밀번호 변경 / 이메일 / 로그아웃
2. 알림: 항목별 토글(예약 확정 / 시작 5분 전 / 자동 취소 / 워크룸 자리 남) + 조용한 시간
   (채널 선택은 없앴습니다 — 브라우저/앱 알림 한 가지라서)
3. 내 예약·이용: 다가오는 내 예약 / 이번 달 노쇼 횟수 / 이용 기록 바로가기
   → 노쇼 횟수 = 내 예약 중 status:'cancelled' 개수
4. 개인화: 다크 모드 / 기본으로 열 자원 / 가이드 다시 보기(10단계 재실행)
5. 관리(admin 만): 현황 대시보드(7단계) / 운영시간 / 자동취소 시간 / 멤버 관리

[완료 조건]
- 프로필 클릭 → 마이페이지. 모바일은 전체화면, 데스크탑은 가운데 시트
- role !== 'admin' 이면 관리 구역이 아예 안 보임
- 알림 항목을 끄면 9단계에서 그 알림이 실제로 안 감
- '가이드 다시 보기' → 온보딩 전체 재실행
- '기본으로 열 자원'을 바꾸면 다음 접속에 그 자원부터 열림
- 노쇼 횟수가 cancelled 예약 수와 일치
````

## 5. 단계마다 반복할 마무리 루틴

```bash
npm run build          # 빌드 깨졌는지
git add -A && git commit -m "step N: ..."
git push               # → Vercel 프리뷰 URL 생성
```

프리뷰 URL을 **데스크톱과 휴대폰 양쪽에서** 열어보세요. 기본 사용은 데스크톱이지만 PWA로도 깔리기 때문에 좁은 화면에서 자원 알약이 줄바꿈되고 모달이 잘리지 않는지 확인해야 합니다.

확인 항목 4개:

- [ ] 라이트/다크 양쪽에서 정상
- [ ] 데스크톱 1280px 와 휴대폰 양쪽에서 레이아웃이 안 깨지는지
- [ ] 로그인 안 한 상태로 접근했을 때 튕기는지
- [ ] Firestore 콘솔에서 실제 문서 모양이 AGENTS.md 스키마와 같은지

## 6. 마지막으로

1단계는 만들고 나서 화면에 아무 변화가 없습니다. 하루를 썼는데 눈에 보이는 게 없으면 "그냥 워크룸부터 만들걸" 하는 생각이 들 겁니다.

그때 확인해볼 것은 하나입니다. **Firestore에서 회의실 운영시간을 바꿨을 때 배포 없이 화면이 바뀌는가.** 이게 되면 나머지 여섯 단계가 전부 그 위에 얹힙니다. 안 되면 3단계쯤에서 코드가 두 벌이 되기 시작합니다.

지금 회의실 예약이 이미 돌아가고 있으니, 이 정리를 하기에 지금이 가장 쌉니다. 자원이 네 개가 된 다음에는 네 배로 비싸집니다.
